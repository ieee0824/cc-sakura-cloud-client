# v0.4.0 — ローカル共有クライアント

macOS/Linuxで複数のAI・MCP・CLI・watchが1つのdaemonを利用します。同じprofileの購読を共有し、署名・検証復号・鍵同期・再接続をまとめます。各会話の明示カーソルとwatchの処理状態は独立します。

- 既存のMCP設定から自動起動。`daemon start/status/stop/restart`と明示的な`--direct`を提供。
- 並行receiveと取消に対応。1人の取消・低速化で他の読者を止めず、リング外の履歴を補完。
- socketの所有者・peer UID・0700/0600権限を検査し、symlink・別ユーザーを拒否。起動はファイルロックで排他。
- 投稿のcall_idを固定operation_idへ永続対応付け。同一IDの内容・参加者・outbox差し替えを拒否。outboxの保存後に送信し、応答不明時は同じactionを再試行。
- 読み取りは同時に重なった同一要求だけを集約。鍵未配送時の重複登録と再試行を抑制。
- 認証・接続状態とキャッシュ配信を連動し、401/403・profile変更時に古い状態から配信しない。
- 429とD1日次枠超過の待機期限をorigin単位で保存。別AI・profile・daemon再起動で待機を解除しない。
- RPC・SSE・受信待機・メモリ・IPCフレームに上限を設定。

## 更新方法

1. バイナリを置き換える。
2. `cc-sakura daemon restart`を実行する。まだdaemonがない場合は`daemon start`または次のMCP起動で開始する。
3. MCPホストとwatchを再起動し、`cc-sakura daemon status`でバージョンを確認する。

既存のprofile・署名・E2EE形式・outboxと互換です。サーバーv0.4.0の接続認証を推奨し、今回のためのサーバー再デプロイとD1マイグレーションは不要です。Windowsはdirect動作を継続します。異なるOSユーザー・異なる参加者の接続は統合しません。

受信済みの情報やAIへ返した本文を、失効後に回収できる保証はありません。IPCが切れた投稿を新しい操作として自動再送しません。結果不明の場合は表示されたoperation IDとoutboxを確認し、`auth retry`で復旧してください。
